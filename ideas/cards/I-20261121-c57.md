## 问题（一句话）
不用真值：先用生产前端（整数网格）的原子按 |增益|² 加权求共同多普勒 ĉ（取到 .25），再只在 [ĉ − 1, ĉ + 1] 上用 .25 网格（9 点/时延）重跑第 0 轮 OMP，FER 是否显著低于完整 .25 网格（c48）。

## 白话与类比
c56 证明"少搜一半"有用，但用了真值符号。这里先粗看一眼大致方向，再只在那附近细找。

## 锚点（出处）
- D：c56（真值符号先验，b − c = 31）；c29/c33 的共同多普勒思路。

## 去壳三句
1. 谁真卡住了：c56 不可部署；生产和 c48 前端都对称搜索。
2. 解决了会改变什么：若成立，前端可改为"粗估 → 窄窗细网格"，FER 比 c48 再降、CPU 比 c48 低。朴素替代：c48 的完整 .25 网格（对照臂）。
3. 难处的结构：粗估 ĉ 来自整数网格，会偏向整数；窗要宽到容忍偏差，又要窄到减少噪声列。

## 推导（项目数字）
- 列数 103 × 9 = 927（g25 为 1751）；噪声最大相关约按 sqrt(2 ln K)：3.70 vs 3.86（−.37 dB），与 c56 相同。
- 场景 U 真多普勒 .30–1.73；若 ĉ ∈ [.75, 1.25]，窗 [ĉ − 1, ĉ + 1] 覆盖全部真径。实测 ĉ 的 10/50/90 分位为 .25/.50/.75，窗完全覆盖 [.25, 1.75] 的帧只有 33%，即多数帧窗口切掉了部分高多普勒区间，结果仍与真值先验持平。
- 实测（adapt vs g25）：rho = .10 FER .323 [.279, .370] → .263 [.222, .308]（b 44, c 20）；rho = .15 .117 [.090, .153] → .083 [.059, .114]（b 22, c 8）；合并 b − c = 38，p = .0001。adapt vs pos25（真值先验）合并 b − c = 0。F0 CPU .285 → .225 s（比 c48 少 21%）。

## 问题（一句话）
场景 G 的真多普勒在 [−1.62, 1.62] 双边对称；c57 的 [ĉ − 1, ĉ + 1] 窄窗（.25 网格）在 G 上相对完整 g25 是否不亏。

## 白话与类比
在单边场景里按重心开一个 2 bin 宽的窗很好用；换到两边都有径的场景，窗还盖不盖得住。

## 锚点（出处）
- D：c57（场景 U 上不用真值的窄窗 b − c = 38）；`probe5.py`（G 多普勒双边，正号 52%）。

## 去壳三句
1. 谁真卡住了：c57 作为"可部署方案"的说法；跨模型审一定会问双边场景。
2. 解决了会改变什么：若 G 上不亏，c57 可直接当前端默认；若亏，c57 只能当"有先验时"的做法，部署需要先估扩展而不是重心。
3. 难处的结构：重心 ĉ 在双边信道上接近 0，而径分布在两端。

## 推导（项目数字）
- 列数：窗 9 点 × 103 = 927 vs g25 1751。噪声最大相关 sqrt(2 ln 927) = 3.70 vs sqrt(2 ln 1751) = 3.87（−.39 dB）。
- 覆盖：G 真多普勒四分位 −1.10 / .13 / 1.16（`probe5.py`），|k| > 1 的径约占一半；ĉ 落在 0 附近时窗 [−1, 1] 盖不住约一半径（跑前预计不利，但未定量）。
- 实测（adapt vs g25）：rho = .10 FER .315 [.271, .362] → .573 [.524, .620]（b 17, c 120）；rho = .15 .117 [.090, .153] → .375 [.329, .423]（b 14, c 117）；合并 b − c = −206，p < 1e−4。对 base 也更差（b − c = −100）。F0 CPU .315 → .242 s。

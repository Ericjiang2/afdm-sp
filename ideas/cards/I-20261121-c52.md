## 问题（一句话）
c48 的 .25 bin 第 0 轮网格在 rho = .075 和 .20 两个工作点上，F0+A1 后的 FER 是否仍显著下降。

## 白话与类比
c48 在 rho = .10/.15 过了线；这里看它是不是只在那一段有用：太弱时救不回来，太强时本来就没什么要救。

## 锚点（出处）
- D：c48 确认批只覆盖 rho ∈ (0.1, 0.15)、snr 450。

## 去壳三句
1. 谁真卡住了：要不要把 .25 网格写进生产前端，取决于它是否在整条 rho 扫描上不吃亏。
2. 解决了会改变什么：若各档都降 FER，可直接作为默认；否则只在中段开。朴素替代：保持整数网格，损失就是 c48 测到的 .04–.07 FER。
3. 难处的结构：网格加密只回收失配损失（平均约 1.1 dB → .07 dB），不改变导频能量；rho 太低时 F0/A1 捕获本身失败，rho 高时失配损失已不是瓶颈。

## 推导（项目数字）
- rho = .075 比 .10 的导频能量低 10·log10(.075/.10) = −1.25 dB；网格回收约 1.0 dB，回收后仍不到 rho = .10 的整数网格水平（其 FER 已 .41–.47），所以预期 rho = .075 FER 仍接近饱和。
- rho = .20 比 .15 高 +1.25 dB，base FER 预期 ≈ .10，剩余可救帧约 20/200，即使全救 b − c 也不过十几。
- 实测：rho = .075 base FER .970 [.936, .986] → g25 .975 [.943, .989]（b = 4, c = 5）；rho = .20 .095 [.062, .144] → .080 [.050, .126]（b = 9, c = 6）；合并 b − c = 2，p = .84。F0 CPU .16 → .29 s（约 1.8 倍）。

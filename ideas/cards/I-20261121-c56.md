## 问题（一句话）
场景 U 的真多普勒全为正（.30–1.73 bin），而生产前端对称搜索 [−2, 2]；只搜 [0, 2] 的 .25 网格（每时延 9 点）FER 是否显著低于完整 .25 网格，即接收机为"不知道多普勒符号"付了多少代价。

## 白话与类比
在一半根本不会有东西的地方找，等于给噪声多发了一倍的入场券。

## 锚点（出处）
- B（pit / 前提检查）：`probe3.py`：场景 U 47000–47039 帧 640 条径全为正。生产 `pilot_front` 和 c48 的 g25 都对称搜索。

## 去壳三句
1. 谁真卡住了：所有在场景 U 上报的 FER（含 c48）都包含对称搜索的代价；如果代价大，场景 U 的数字对"单边多普勒"敏感，论文结论要说明。
2. 解决了会改变什么：若成立，(a) 场景 U 结果应注明这一先验没用；(b) 实际系统可用一个粗的共同多普勒估计（c29 方向）或拖曳方向先把搜索窗半边化。朴素替代：对称搜索（对照臂）。
3. 难处的结构：贪心 OMP 的假原子概率随字典列数上升；列数减半直接减少噪声匹配机会，同时不丢任何真径。

## 推导（项目数字）
- 列数：g25 为 103 × 17 = 1751，pos25 为 103 × 9 = 927（.53 倍）。对零均值高斯噪声，K 列中最大相关的期望约 σ·sqrt(2·ln K)：sqrt(2 ln 1751) = 3.86，sqrt(2 ln 927) = 3.70，噪声最大峰下降约 4%（.37 dB）；24 个名额中相关径只有约 3.26 条（c53），其余 ~20 个名额都由噪声峰竞争，峰更低意味着假原子能量更小。
- 预期 FER 降幅与 c48（1 → .25 bin）同量级。实测（pos25 vs g25，同帧）：rho = .10 FER .395 [.330, .464] → .275 [.218, .341]（b 28, c 4）；rho = .15 .115 [.078, .167] → .080 [.050, .126]（b 11, c 4）；合并 b = 39, c = 8，b − c = 31，p < .0001。相对生产 base：rho = .10 .470 → .275，rho = .15 .160 → .080（合并 b − c = 55）。F0 CPU .282 → .220 s（比 g25 省 22%，比 base 多约 45%）。

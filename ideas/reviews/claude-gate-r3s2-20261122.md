## 卡 B：`I-20261121-l14`

**一句话结论：不值得做。** 结论成立，但这是"多载波峰均比高，在功放上吃亏"的教科书结论换了 AFDM 的名字；1.25 dB 是几种功放处理方式里最乐观的那一档。

**白话与类比。** 两辆车跑同一条限速路，限的是最高速度，不是平均速度。单载波像匀速行驶的车；AFDM 的波形起伏像高斯噪声，像一辆忽快忽慢的车。限了最高速，忽快忽慢的车平均就慢。这本来就是常识。卡唯一可能不平凡的部分，是 AFDM 能否靠"多普勒分集"把这点亏损追回来。实测没追回：两种波形在簇信道上都只变差约 0.45 dB，因为接近最优的迭代接收机下，单载波同样拿到了分集。

**最接近的工作**
1. Falconer、Ariyavisitakul 等 2002，IEEE Commun. Mag. 40(4)：单载波加频域均衡，性能与 OFDM 相当，峰均比更低、功放回退更小，这是 LTE 上行改用 DFT-s-OFDM 的依据之一。只读到摘要和 802.16 教程转述。[802.16 教程](https://grouper.ieee.org/groups/802/16/meetings/mtg11/tutorial.html)
2. Ochiai 2013，IEEE TCOM 61(4):1460–1472：只用包络分布来分析带限单载波和 OFDM 的功放效率与失真之间的权衡。这正是"等峰值功率总退化"比较的分析框架。只读到摘要。[书目](https://researchr.org/publication/Ochiai13/bibtex)
3. Motorola R1-060023 "Cubic Metric in 3GPP-LTE"（2006）：3GPP 用 cubic metric 量化功放降额；DFT-s-OFDM 明显低于 OFDM。没取到原文，只看到二手片段，具体 dB 值没有核实。[片段](https://www.slideshare.net/slideshow/cubuc-metric-in-3-gpp-lte/9836414)
4. arXiv 2405.03119 DAFT-spread AFDMA：已提出 AFDM 的扩频版本来降峰均比，并明确把 SC-FDMA 当作低峰均比的参照。只读到摘要。[链接](https://arxiv.org/html/2405.03119v1)
5. arXiv 2512.17679 A²FDM：同类降峰均比的 AFDM 变体，原文说 AFDM 的峰均比与 OFDM 同量级。只读到摘要。[链接](https://arxiv.org/html/2512.17679v1)
6. arXiv 2111.07398《Single- versus Multi-Carrier Terahertz-Band Communications: A Comparative Study》：峰均比排序为 SC-FDE 最低，DFT-s-OFDM、DFT-s-OTFS 其次，OTFS 和 CP-OFDM 更高。只读到摘要。[链接](https://arxiv.org/pdf/2111.07398)
7. Ochiai、Imai 2002，IEEE TCOM 50(1)：限幅加滤波 OFDM 的 Bussgang 分析，本卡的 α 和失真比就是按这套方法算的。只凭记忆和卡内引用，本次没读。

**查新判断：已被做过。** AFDM 时域样点近似高斯，峰均比与 OFDM 相同（见 2405.03119、2512.17679），所以"AFDM 对单载波"在功放约束下就是"OFDM 对 SC-FDE"，这个比较已有二十多年文献。卡说近期 AFDM 降峰均比论文"回避"了与单载波的比较，这不准确：DAFT-spread 这一支本身就是向单载波靠拢的做法。没见到有人在叠加导频、有限码长的设定下给出这个具体数字，但只是换了个设定。

**为什么没人做：选 (2)，即已被发现，而且结论早有定论。** 业界的应对是 DFT 扩频（LTE 上行、DFT-s-OTFS、DAFT-s-AFDM），不是再测一遍差多少。

**1.25 dB 在别的设定下站不站得住。** 我在本机复算了标定，复现了 runner 在 1.5 dB 门限下的读数：单载波 α = 0.894、失真比 21.3 dB、峰均比 3.36 dB；AFDM α = 0.831、失真比 15.0 dB、峰均比 4.10 dB。之后扫了不同门限：

| 发射处理 | 达到 3 dB 数据信干噪比所需峰值信噪比差（AFDM 减单载波） |
|---|---|
| 两步限幅滤波，门限 0.5 / 1 / 1.5 / 2 / 3 dB | 1.13 / 1.13 / 1.14 / 1.15 / 1.18 dB |
| 门限 4 / 6 dB | 1.06 / 1.57 dB |
| 不限幅、纯线性回退到 99.9% / 99.99% 峰值 | 3.18 / 3.81 dB |

结论：方向在所有设定下都站得住，AFDM 都更差；大小在 1.1–3.8 dB 之间，取决于功放和发射端处理。1.25 dB 是"发射端做激进限幅滤波"的下端。对 QPSK 加大量化前向纠错的低信噪比工作点，这种处理是合理的，但对实际换能器（硬峰值上限、无 DPD）不保证。另外，卡 L1 部分写的不限幅 AFDM 峰均比 9.19 dB 与复高斯理论值（4 倍过采样、10⁻³ 处约 8.4 dB）和我的复算 8.32 dB 都不符，所以"无限幅回退差 4.03–6.01 dB"偏高，实为约 3.2–3.8 dB。

**真实系统里的影响。** 只影响"为什么不用叠加导频单载波"这个审稿问题：本项目论文不能以功放效率为 AFDM 辩护，理由要放在别处。量级是适用范围里的一句话，不改变任何主线参数。

**如果要做，最便宜的一步：** 无需再跑。若一定要补，就加一臂 DAFT 扩频 AFDM 或带 DFT 预编码的变体：在同一管线上，它应当把差距收回到约 0.1–0.3 dB，从而把结论归结为"AFDM 要么付这个代价，要么退化成单载波"，约 1 核时。

## 卡 C：`I-20261122-l09`

**一句话结论：有条件值得做。** 分径这一步干净而且稳健，但卡把真正的难点（16 条径的位置从哪来）和译码一起留在了检验之外。

**白话与类比。** 合唱团里两个人恰好唱同一个开场口令，于是只能听到口令的合声。之后两人各唱各的歌，每个人的声音在厅里有好几处回声。同一个人的几处回声唱的是同一首歌，彼此"对得上"；不同人的回声对不上。只要知道口令合声里每处回声有多响、相位如何，就能逐对判断"这两处是不是同一个人"，从而把回声分成两组。剥掉术语：同源回声彼此相关，不同源回声不相关，再用已知的合声做相干比对。平行四边形恒等式只是把这个判断写成了矩阵形式（同用户的元素是 +s_r s_q*，跨用户是 −s_r s_q*）。思路接近常识，但用在"单天线、同一前导碰撞"上没见人做过。

**最接近的工作**
1. Jagannatham & Rao，"Whitening-rotation-based semi-blind MIMO channel estimation"，IEEE TSP 54(3), 2006：数据的二阶统计盲估出白化矩阵（即 HHᴴ），导频只用来定剩下的酉旋转。卡的"二阶矩留 U(2) 模糊、前导和信道锁定"正是这个结构；差别是本卡用径域代替天线，而且两个用户共用一个导频。只读到摘要。[dblp](https://dblp.org/rec/journals/tsp/JagannathamR06)
2. Müller、Cottatellucci、Vehkaperä，"Blind pilot decontamination"，IEEE JSTSP 2014：用数据协方差的子空间分离导频污染的用户，依赖大规模天线下特征值分团。本卡用 16 条径代替大量天线。只读到摘要。[arXiv 1309.6806](https://pdf.arxiv.org/pdf/1309.6806)
3. Ngo & Larsson，ICASSP 2012，基于特征分解的信道估计：用接收数据协方差的特征分解盲估信道，再用短导频消除歧义，前提是天线很多。只读到摘要。[QUB](https://pure.qub.ac.uk/en/publications/evd-based-channel-estimations-for-multicell-multiuser-mimo-with-v/)
4. Tsatsanis、Zhang、Banerjee 2000（NDMA）与 Zhang、Tsatsanis 的 B-NDMA 及多径扩展：把随机接入的碰撞消解当作盲源分离，但需要 k 到 k+1 个时隙的重传来构造混合矩阵。本卡想在单帧内完成。只读到摘要和二手描述。[检索来源](https://arxiv.org/pdf/cs/0610104)
5. Björnson、de Carvalho 等，SUCRe（arXiv 1604.04248）：大规模 MIMO 中同一导频碰撞后由最强用户胜出，依赖多天线。只读到摘要。[arXiv](https://arxiv.org/abs/1604.04248v1)
6. Bergamasco、Clazzer、Casari，OTFS-IDMA（arXiv 2601.13065，ICC 2026）：论文存在，是双色散信道下的无源多址方案。卡称它"明确指出前导碰撞瓶颈"，我没读全文，不能确认原话。[arXiv](https://arxiv.org/abs/2601.13065)
7. 5G NR 两步接入的工程讨论：同一导频（DMRS）碰撞被视为不可解，对策是增加 DMRS 端口，或退回四步接入。只读到 Peralta 等的论文和专利摘要。[Tampere 论文](https://trepo.tuni.fi/bitstream/10024/134854/1/Two_Step_Random_Access_in_5G_New_Radio.pdf)

**查新判断：部分被做过。** "数据二阶统计加导频定旋转"是已知的半盲估计结构（第 1 条）；"用数据子空间分离撞导频的用户"在多天线下已有（第 2、3 条）。没见到"单天线、以多径为虚拟阵元、单帧内分开同一前导碰撞"的工作。

**为什么没人做：选 (3)，即发现了，但有隐藏代价。** 卡回避了三处代价。
1. **径的位置拿不到。** 256 点前导的多普勒分辨率是 1/(256 Tₛ)，换算成 1024 点帧的格数是 1024/256 = 4 格，比项目全部多普勒范围（±1.62 格，宽 3.24 格）还宽。所以碰撞前导只能分辨时延，分不出多普勒。而分径要用每条径的精确多普勒做反移位，误差 0.5 格就会在 1024 点上严重失相关。并集位置要么来自数据段（又是盲估问题），要么来自全长导频（叠加导频的第 0 轮找径，正是本项目的老瓶颈）。
2. **码率必须事先压低。** 用户发送前不知道会不会碰撞。要让碰撞包可译，所有包都得用 R ≤ 0.38（卡自己的要求），没碰撞的包也一起付约 24% 的速率代价（相对 R = 1/2）。
3. **多天线接收机已经能做空间分离。** 只有单天线场景（水声网关、单端口星载）才真正需要它。

**扰码与数据相关性的问题。** 在 NR 里，msgA PUSCH 的扰码初值里含前导号，撞同一前导的两个用户很可能用同一扰码；这一点我凭记忆，没核 TS 38.211 原文。但扰码相同不会让数据相关：只要两人的载荷比特独立，扰码后 E[x_A x_Bᴴ] 仍为 0，有限长度下的残余约为 1/√N，L2 用独立 QPSK 已经包含这一项。会破坏恒等式的只有相同的已知部分：共用的 DMRS 或叠加导频（已知，可以先减掉），以及完全相同的载荷段（相同报头、填充）。若两人发的消息完全相同，D = ssᴴ，方法会把所有径分给同一人；但这时用和信道直接译码就够了，问题本身消失。

**单天线、两个等功率用户能否译出。** 每用户 8 dB 时，总速率 1.33 bit/样本，远低于和容量 log₂(1 + 2·6.31) ≈ 3.77 bit。第一轮把对方当噪声时，LMMSE 信干噪比约 −0.6 dB，QPSK 互信息约 0.4 bit/比特，略高于 R = 1/3。原理上可行，但没测过。

**真实系统里的影响。** 如果所有两用户碰撞都能救回，时隙 ALOHA 类接入的最大吞吐从 1/e ≈ 0.37 升到 0.84（S = G e^{−G}(1 + G)，在 G = 1.62 处取最大），可以改变前导池大小与碰撞恢复架构的设计。但前提是单天线、并集位置可得、低码率代价可以接受；三条里第一条目前不成立。

**最便宜的一步检验（先于写双用户译码器）：** 去掉"已知 16 条径位置"这个前提。只给接收机碰撞前导能提供的信息（时延，加上 4 格分辨率的多普勒），然后 (a) 用数据段跨径统计在时延格内细搜多普勒，或 (b) 用全长叠加导频（ρ = .25）估并集支撑，再测分错功率比例。若中位数仍 ≤ 5%，第 2 步译码才值得写。纯 numpy，约 0.05 核时。

### 放行

**最强反对意见。** L2 的通过建立在"接收机已知 16 条径的精确时延和多普勒"上，而 256 点前导连多普勒都分辨不了（分辨率 4 格，大于 ±1.62 格的整个范围）。卡把最难的一步当成了已知条件。卡给的价值"可独立成一篇 TCOM / TWC 论文"在支撑获取和译码都没测之前是夸大。

**我做了两项压力测试，结果对卡有利：**
- 放开"16 条时延互不相同"的限制，时延均匀抽取时，约 48% 的抽样里两用户有同时延的径。分错功率比例中位数 0.00%，均值 0.82%，超过 5% 的抽样占 3%。
- 改用接近生成器的指数时延（两用户首径都在 0），同时延的概率为 1，"同时延且同整数多普勒格"的概率为 41%。中位数 0.26%，均值 0.81%，超过 5% 的占 2.5%。

所以在位置精确已知时，同时延不是问题，只要连续多普勒不同就能分开。问题集中在位置获取上。

**锚点核对**
- Bergamasco 等 2601.13065：存在。"明确指出前导碰撞瓶颈"没有核到原文。
- Mirri 等 2507.22013：存在（检索中出现），细节未核。
- Xu 等，TCOM vol. 74, pp. 840–853, 2026；Mehrotra 等 2503.23540；Li 等 2405.11883：本次没有核实，不能确认存在与卷页。
- Perry、Wein、Bandeira、Moitra，Ann. Statist. 46(5) 2018：存在。但用 BBP 相变（大维渐近）去标定 K = 16 的小矩阵不合适；卡里的"95.2% 重叠率、+13.2 dB"不能当证据，应以仿真为准。
- 3GPP 碰撞率：64 个前导、16–25 个用户时，碰撞率 21–32%，按 1 − (63/64)^{k−1} 计算正确（实际可用于竞争的前导通常少于 64）。
- 卡缺了最该引的两条：半盲白化–旋转（Jagannatham–Rao）和盲导频去污染（Müller 等）。
- 检验设定里的"2N·c1 = 9"已在筛选记录中注明是误读；L2 用的是纯时域时延–多普勒模型，不涉及这一参数。

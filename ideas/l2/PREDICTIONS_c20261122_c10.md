# L2 云端 runner c，卡 I-20261122-c10：跑前判据与预测（2026-11-22 15:45 写，运行之前冻结）

问题：硬基线把 ρ 定在 .25（1% 穿越点 4.95 dB）是在"接口全取 1"的接收机上选的。c08 表明接口失配随 ρ 降低而加重（ρ = .25 几乎没有，ρ = .10 占失败的三分之二）。接口按 ρ 标定后，ρ = .15 或 .20 是否在 4.5 / 5.0 dB 上比 ρ = .25 更好？

- 脚本同 c08（`c_l2_c08_iface.py`，网格与学习规则不变）。训练：`C08_RHO=150` 与 `C08_RHO=200`，`C08_SNRS=450,500`，帧 41460–41559，输出 `out_c10r15/`、`out_c10r20/`。
- 测试（新帧 42160–42359，U/G，4.5 / 5.0 dB，各 800 行）：ρ = .15 学到的设定、ρ = .20 学到的设定、ρ = .25 原设定与学到的设定（`out_c10r25/`，沿用 `out_c08r25` 的训练结果）。同一帧号在不同 ρ 下信道与数据相同，按帧号配对。
- 基线：ρ = .25 的两臂里误帧率较低的那个。
- **通过**：ρ = .15 或 .20（跑前不知哪个，两个都报，按 Bonferroni 用 97.5% 区间）学到的设定，误帧率比基线相对低 ≥ 25%，配对 bootstrap 下界 > 0。**淘汰**：两个 ρ 都不比基线低（差 ≤ 0）。其余停放。
- 预测：ρ = .20 学到的设定与 ρ = .25 基线持平（差在 ±1.5 个百分点内，.6）；ρ = .15 更差（.6）；通过 .15。理由：原设定下 ρ 从 .25 降到 .10 损失很大，其中接口只占一部分，剩下是第 0 轮捕获。

# 预注册：相位噪声「找径地板」小检查（2026-11-24，测试帧 54000–54299 运行之前）

脚本 `ideas/l2/l2_r8_pn_margin.py`（新增 `floor` / `floor_read` 模式，不改已有函数行为）；输出 `ideas/l2/out_r8_pn_floor/summary.json`。不建新卡、不改任何已有卡片；`ideas/l2/PREDICTIONS_r8_pn_margin.md` 及其 `PASS_PRIMARY = false` 判定不变。

## 背景与问题
余量生死检（测试帧 53000–53199，σ² = 0.0164）里，全盲对手 `BEST` 在 G 场景 6.0 / 6.5 / 7.0 dB 留有 9% / 7% / 6% 的误帧尾巴（U 场景 2% / 0.5% / 0.5%），而白送第 0 轮真径的 `BESTGA` 在 6.5–7.0 dB 两场景均已降为 0%。本小检查只回答一个问题：这条尾巴是否一直拖到高 SNR（7–12 dB）形成「找径错误地板」。

## 设定（跑前写死）
- 接收机与常数：沿用 `ideas/l2/l2_r8_pn_margin.py` 与已冻结的 `dev_v5` 常数（`ideas/l2/r8_pn_margin_constants.json`，与 `ideas/l2/out_r8_pn_margin/dev_v5_constants.json` 一致：`mode = kf` 卡尔曼前后向平滑、`src = app` 译码后验、`infl = 3.0` 噪声膨胀 ×3、`a0 = 0.06`、`a1 = 0.2`、`ao = 0.25`、`kap = [0.10, 0.05]`）。
- 信道与相噪：ρ = 0.30（`RHO = 300`），接收端维纳相噪每样点增量方差 σ² = 0.0164（`SIG2[0]`）；同帧跨臂、跨 SNR 共用同一信道实现、噪声底与相噪轨迹（`SEED = 20261124`）。
- 臂：`BEST`（全盲分段非相干找径 + 四变体校验重试）、`BESTGA`（仅第 0 轮导频模型白送真径，其余与 `BEST` 相同跟踪链）、`CLEAN`（无相噪项目接收机 F0 + CODELAY 基线）。
- 场景：U 与 G 分开统计（不合并判定）。
- SNR：7、8、9、10、11、12 dB（共 6 档，跨度 5 dB；脚本内部编码 `700, 800, 900, 1000, 1100, 1200`）。
- 帧集：全新帧 54000–54299（每场景 300 帧，共 300 × 2 × 6 = 3600 键）；不用开发帧 52000–52039 与余量测试帧 53000–53199。
- 预算硬上限：预期约 3 核时；超过 5 核时自动停机并报告，不输出有效判定。

## 竞争假设
1. **H1（找径地板存在）**：相噪导致当前盲找径（分段非相干搜索 + 奇异向量公共相位初值 + `pilot_front` 交替 3 遍）在部分信道/相噪实现上失锁，即便导频加性噪声随 SNR 升高大幅下降仍无法解脱。预测：G（或 U）场景下 `BEST` 在 7–12 dB 每一档误帧率持续 ≥ 1%，同场景 `BESTGA` 在 12 dB ≤ 0.5%，`CLEAN` ≈ 0%。
2. **H2（缓降尾巴，非地板）**：6–7 dB 的 9% / 7% / 6% 只是斜率较缓的过渡尾巴，随 SNR 升至 8–12 dB 盲找径失锁迅速消失。预测：U 与 G 场景 `BEST` 在 7–12 dB 内至少有一档跌破 1%，`BESTGA` 与 `CLEAN` ≈ 0%。
3. **H3（跟踪端地板而非找径地板）**：高 SNR 残余误帧来自相位跟踪本身而非第 0 轮找径。预测：同场景 `BESTGA` 在 12 dB 仍 > 0.5%（按 53000–53199 在 6.5–7.0 dB 已为 0% 来看，可能性极低）。

## 预注册判据（跑前提交锁定，跑后不改）
- **`FLOOR_CANDIDATE`**：在 U 或 G 任一场景里，`BEST` 在 7、8、9、10、11、12 dB **每一档**误帧率都 ≥ 1%（300 帧精确等价于每档错帧数 ≥ 3，跨度 ≥ 5 dB），**且**同场景 `BESTGA` 在 12 dB 误帧率 ≤ 0.5%（300 帧精确等价于错帧数 ≤ 1，说明尾巴来自找径而不是跟踪）。成立只说明「值得查」，不建卡，也不直接宣称存在物理极限地板。
- **`CLOSED`**：其余情况，相位噪声这条线收官。

## 设计有效性核对
- **单因子对照**：`BEST` 与 `BESTGA` 仅差第 0 轮找径（盲找径四变体重试 vs 白送真径），跟踪平滑器、软符号回送与最终 F0 + CODELAY 一致；`CLEAN` 确认无相噪接收机本身在 7–12 dB 无地板。
- **统计功效**：已有 53000–53199 在 G 场景 7.0 dB 上 `BEST` 误帧率 6.0%（12/200）、`BESTGA` 0%（0/200）。新帧每场景 300 帧，若真实地板维持 4%–6%，单档期望错帧 12–18 帧，远高于 1%（3 帧）门槛；若无地板（< 0.3%）则几乎不会跨过 3 帧。
- **统计单元**：以帧为独立单元（同帧跨 SNR 共用信道与相噪轨迹）；按 U / G 场景分开汇总，每场景 300 帧。
- **代理/白送臂含义**：`BESTGA` 仅代表「找径零失误时现有跟踪链在高 SNR 的错误率」，不代表信息论下界；`CLEAN` 为无相噪基线。

## 事前验尸（Premortem）
- 若判 `FLOOR_CANDIDATE`：最可能的误读是把「拼装盲找径实现的缺陷」当成「相噪本身的物理地板」。本实验**不能**排除实现偏弱，因此成立只记「值得查」，不建卡。
- 若判 `CLOSED`：可能真实地板落在 0.3%–0.8%（低于 1% 门槛）或仅在更强相噪下出现；在该工程门槛下按预注册收官。

## 跑前预测账本（agy Gemini 4 Neon）
- G 场景 `BEST` 在 7 dB 误帧率约 4%–8%，随 SNR 升至 12 dB 衰减缓慢并持续 ≥ 1%（预期 2%–5%）：概率 65%。
- U 场景 `BEST` 在 7 dB 约 0.5%–1.5%，在 7–12 dB 内跌破 1%：概率 80%。
- U 与 G 两场景 `BESTGA` 在 12 dB 均为 0%（≤ 0.5%）：概率 95%。
- U 与 G 两场景 `CLEAN` 在 7–12 dB 均为 0%：概率 99%。
- 最终判定：`FLOOR_CANDIDATE` 65%，`CLOSED` 35%。

## 已知局限（跑前写明）
- **`BEST` 是用现成部件拼的盲找径**（分段长 32/64、8 径非相干搜索、奇异向量公共相位初值 + `pilot_front` 交替 3 遍 + 四变体校验重试），**地板可能来自实现偏弱而非相噪本身**。
- 只测单档相噪 σ² = 0.0164、单天线接收端相噪、固定导频比 ρ = 0.30 与已冻结的 `dev_v5` 常数（未对 7–12 dB 重新调参）。
- 每场景 300 帧，在 1% 门槛（3 帧）附近存在二项抽样涨落。

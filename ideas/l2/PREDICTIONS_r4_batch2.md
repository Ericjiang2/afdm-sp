# 本地第 4 轮 L2 第 2 批的跑前判据（卡 I-20261122-l34；2026-11-22 17:45，runner l）

问题：`res-20261118-03` 里 SBL 各臂用固定增益检测器（`e3_driver.detect_decode` 写死 `gain_mode='fixed'`），CODELAY 一侧用联合增益。把 SBL 臂的检测器在**两轮都**换成联合增益（其余不动：同一套 E-3 的筛选、SBL、LDPC、两轮），SBL 的误帧率变多少？

已经看过的：卡片自己的探针（每格 4–10 帧，联合增益下 L-hard、L-cov 明显变好）；项目试点 5（`experiments/sbl_joint_detector_20261019/SUMMARY.md`：只在第 2 轮换，L-diag .024 → .101 变差，L-cov .088 → .018 变好；ρ = .3、7–8 dB、帧 9100–9299）；`res-20261118-03` 的归档数字。没有看过：本批要用的帧上"两轮都换"的任何读数。

设定（写死）：
- 脚本 `ideas/l2/l2_r4_sbl_joint.py`，在 deinlab 运行；`e3_driver.process_key` 原样导入，只把 `detect_decode` 换成 `gain_mode='joint'`（迭代 20、阻尼 .3 不变），第 1 轮和第 2 轮都换。变体 L-hard、L-diag、L-cov。
- 帧 4000–4059（`res-20261118-03` 同批帧的前 60 帧），U 与 G，ρ = .30 与 .50，SNR 6 / 7 / 8 / 9 dB，共 960 键。固定增益臂直接取归档行（`experiments/tf_e3_sbl_20261017/out/main/`，同键配对）。
- 实现门（跑前）：不打补丁时，8 个归档键上三个变体的 `decoded_sha256` 与归档逐一相同；不过就不跑。
- 联合增益检测器数值报错的键：该键（第 1 轮报错）或该变体（第 2 轮报错）记为误帧，并报次数。
- 读数：每个 (ρ, 变体) 在 7 与 8 dB 合并（U、G 合并，240 键）的误帧率，固定对联合；配对差的 95% 区间按 60 个物理帧整群自助 2000 次。另报各 SNR 的误帧率表、第 1 轮零校验子的比例（固定对联合）。
- 估计算力：约 2–3 CPU 核时（上限 5）。

判据：
1. 对每个 (ρ, 变体)："联合增益明显更好" = 联合的合并误帧率 ≤ 固定的一半，且配对差的区间不含 0；"联合不更好" = 配对差的区间含 0 或偏向固定；其余记"变好但不到一半"。
2. 主表上端（L-hard，ρ = .30）：若"明显更好"且联合臂在 8 dB 的误帧率 ≤ 3%，卡片关于"+5 dB 这一端主要来自检测器接口"的说法成立；若"联合不更好"，这半边被否。
3. 主表下端（最强 SBL）：取 ρ = .30 下六个配置（三变体 × 两种检测器）里合并误帧率最低者。若最低者是某个联合配置且它 ≤ L-diag 固定的一半（区间不含 0），则"对最强 SBL 的领先也被高估"成立；否则下端（现稿的 +1.8–3.0 dB）不受影响。
4. 不做的事：不改 SBL 本身（网格、剪枝、迭代数），不重跑 CODELAY，不测耗时；耗时只报"第 1 轮已零校验子的比例"作为早停能省多少的上界。

预测（主观概率）：判据 2 成立 .65；判据 3 成立 .30；ρ = .50 下 L-hard"明显更好" .40；L-diag 在 ρ = .30 "联合不更好" .60。卡片的预言（供打分）：L-hard 的差距缩到 +1.3–2.3 dB（即联合臂的 1% 穿越点约 6.5–7.5 dB，8 dB 误帧率应 ≤ 约 1%）；L-diag 缩到 +0.8–1.5 dB（7 dB 误帧率应 ≤ 约 2%）。

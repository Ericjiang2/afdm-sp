# 预注册：相位噪声余量生死检（第 8 轮 runner l，Eric 批准的规则候选 7；10:48 写，测试帧运行之前）

脚本 `ideas/l2/l2_r8_pn_margin.py`；输出 `ideas/l2/out_r8_pn_margin/`。没有卡片，这是草稿 18 的决定性检验。

## 问题
项目接收机（F0 两个外轮 + 校验失败时 CODELAY 重搜，真实 LDPC）下，接收端维纳相位噪声让 10% 误帧率门限上移多少——对手是现有部件的最强组合。

## 设定（跑前写死）
- 场景 U 与 G 合并；ρ = .30；SNR 4.0–7.0 dB 每 0.5 dB；每样点相位增量方差 σ² = 0.0164（主判）与 0.0082（辅，只作读数）。
- 开发帧 52000–52039（只用来选平滑常数与分段长，SNR 5.0 / 6.0 dB，σ² = 0.0164）；测试帧 53000–53199（本轮没有看过）。帧 52000 已在实现门和调试里用过。
- 各臂同帧、同噪声、同一条相噪轨迹（种子由帧号与场景定，跨 SNR 相同）。
- 臂：`CLEAN` 无相噪；`IGN` 有相噪不处理（健全性对照，不进判据）；`BEST` = 分段非相干找径 + 段间公共相位的奇异向量初值 + 导频模型上相位跟踪与 `pilot_front` 重找径交替 3 遍 + 校验不过时用末轮的径与软符号重建整段信号重跟踪（≤ 3 次）+ 项目自带的 CODELAY 重搜；`ORACLE` = 用无噪无相噪的真接收信号当相位参考（白送真值，只作上限）。`BEST` 的每个部件都是已有做法，不含新方法。
- 10% 门限：两场景合并的误帧率对 SNR 做对数线性内插取首次穿越点；到 7.0 dB 仍不过的记为 7.5 dB 并标删失。区间按帧自助抽样 2000 次。

## 判据（至多两条，同时成立才算「有余量」）
1. `BEST − CLEAN ≥ 1.0 dB`（σ² = 0.0164）。检验的假设：现有部件最强组合在已发表的最强相噪档仍亏 ≥ 1 dB。不成立意味着现有做法已经够，账本门槛的前半条不满足。
2. `ORACLE − CLEAN ≤ 0.5 dB`（σ² = 0.0164）。检验的假设：相位若跟得准，损失可以回到 0.5 dB 内，即差距是可收的而不是基本限。不成立意味着这一档的相噪连白送真值都回不来，没有方法可立。
- `verdicts.PASS_PRIMARY = 判据 1 且 判据 2`。为 false 即判无余量，漏斗收官的依据成立；为 true 只说明余量存在，不说明有办法收。

## 跑前预测（runner l）
- `ORACLE − CLEAN`：0.3–0.6 dB（探针给的理想判决下界 0.32–0.36 dB，加上估计器在残余相噪下的损失），判据 2 多半成立但贴线。
- `BEST − CLEAN`：1.0–2.0 dB（帧 52000 上 5.5–6 dB 能译、4.5 dB 不能），判据 1 多半成立。
- 所以我预测 PASS_PRIMARY = true 的可能性略大于一半；最可能翻掉它的是判据 2。
- σ² = 0.0082：`BEST − CLEAN` 约 0.5–1.0 dB。

## 已知的局限（跑前写明）
- `BEST` 是我在两小时内用已有部件拼的，不保证是文献里最强的；若它过不了而更强的现成做法存在，判据 1 会高估余量。跑前交 `Sol` 做拆台。
- 平滑常数只在 40 个开发帧、两档 SNR 上选；`ORACLE` 的常数同样在开发帧上选。
- 只有接收端相噪，没有发射端相噪；单天线。

## 跑前修订 2（��依据开发帧上的 `dev` 第 2 版与诊断 `diag_v1`，测试帧 53000–53199 仍未运行）
开发帧读数（σ² = 0.0164）：第 2 版 `BEST`（单次、盲找径）在 4.5 / 5.5 dB 的误帧率约 0.9 / 0.45，四个平滑 / 分段变体相近；诊断里把第 0 轮导频模型换成真径后为 0.86 / 0.24 / 0.01（4.5 / 5.5 / 6.5 dB），盲的为 0.90 / 0.45 / 0.25；`ORACLE` 为 0.0125 / 0。我判断第 2 版 `BEST` 作为对手太弱，直接跑会让判据 1 被弱对手抬过线，所以在看测试帧之前把对手加强、把判据改严：
1. 新增对手 `BESTGA`：第 0 轮的导频模型由**真径**给出（白送找径），其余全盲——一轮译码后立即重跟踪，之后每次两轮 F0 校验不过再重跟踪，至多 8 次，最后 F0 + CODELAY。
2. 盲对手 `BEST` 加校验驱动的重试：四个变体（单极点 / 卡尔曼 × 32 / 64 段）依次试，最终输出过校验即停（项目已有的做法）。判决回送同样至多 8 次。
3. 两个对手共用、在开发帧（5.5 / 6.0 dB，`BESTGA` 上）选的三个开关：平滑方式（单极点 / 卡尔曼）、重跟踪用译码后验还是检测器外信息、是否把残余相位误差折成噪声加进接收机的噪声方差（第 0 轮按 0.10 rad²、重跟踪后按 0.05 rad²，取自诊断的中位数）。`ORACLE` 固定用卡尔曼平滑（第 2 版开发帧 1 / 160 对 2 / 160）。
4. **判据 1 改用 `OPP`**：逐键取 `BESTGA` 与 `BEST` 中较好的一个（任一译对即算对，等于白送「选哪一个」）。`OPP − CLEAN ≥ 1.0 dB` 才算判据 1 成立。这个对手同时白送了找径和选择，比任何真实的现有部件组合都强，所以判据 1 只会更难过。判据 2 不变（`ORACLE − CLEAN ≤ 0.5 dB`）。
5. 已知的不对称（都对判据 1 不利，即保守）：对手带多次重跟踪 / 重试，`CLEAN` 只有一次 F0 + CODELAY；实现门里帧 52000 的 G 4.5 dB 一键上盲对手译对而 `CLEAN` 译错。
6. 网格与帧：`CLEAN`、`ORACLE` 在 3.5–7.0 dB（8 档，下扩一档防删失；3.0 dB 省去——开发帧 4.5 dB 处 `ORACLE` 误帧率 1%，10% 点不可能低于 3.5 dB，若低于则按区间记删失）；对手只在 4.5–7.0 dB 跑（4.5 dB 处开发帧误帧率 0.85–0.9）。σ² = 0.0164：全部 200 帧；σ² = 0.0082（辅）：`ORACLE` 200 帧、`BESTGA` 前 100 帧、不跑盲对手；`IGN` 只在前 10 帧跑（健全性）。
7. 算力：估约 8 核时（盲对手四变体重试占一半），超过漏斗 L2 的 5 核时惯例；deinlab 16 进程约 30 分钟。
8. 跑前预测更新：`OPP − CLEAN` 1.0–1.6 dB，`ORACLE − CLEAN` 0–0.3 dB；PASS_PRIMARY = true 的可能性约七成，最可能翻掉它的是 `OPP` 落在 0.8–1.0 dB。

# 实现方案：Turbo-AI Channel Refiner (Stage-2 CE)

**项目**: AFDM水声通信系统深度学习接收机
**阶段**: 第二阶段 - Turbo-AI 信道精炼器
**日期**: 2026-03-08
**状态**: 📋 计划制定中，还没开始改代码

---

## 一、目标

构建 Stage-2 Channel Refiner，利用 Stage-1 输出的软信息作为引导，让第二次信道估计的 NMSE 从 0.20 降到 **0.15 以下**。

---

## 二、核心思想

**冻结 Stage-1，训练轻量级修正网络**

- Stage-1 已经能输出正确的软信息 $(\mu_x, v_x, LLR)$
- Stage-2 网络不再只看原始接收信号 $y$，而是看包含软信息的全景图
- 用 8 通道特征张量训练一个轻量级 3 层 ResNet

---

## 三、网络架构

### 3.1 输入特征（8 通道）

| 通道 | 内容 | 维度 |
|------|------|------|
| 2 | 残差网格 $y - H_1(x_p + \mu_x)$ | (B, 2, L, W) |
| 2 | Stage-1 信道估计 $\hat{H}_1$ | (B, 2, L, W) |
| 2 | 软符号均值 $\mu_x$ | (B, 2, L, W) |
| 1 | 软符号方差 $v_x$ | (B, 1, L, W) |
| 1 | 置信度 $\|LLR\|$ | (B, 1, L, W) |

### 3.2 网络结构

```
Input: (B, 8, 51, 13)
   ↓
Stem: Conv2d(8, 64, 3×3) + BN + ReLU
   ↓
3× Asymmetric Dilated ResBlock (d_H=[1,2,4], d_W=1)
   ↓
Head: Conv2d(64, 2, 1×1)
   ↓
SoftThreshold (独立学习阈值)
   ↓
Output: ΔH (B, 2, 51, 13)
   ↓
H_2 = H_1 + ΔH
```

**参数量**: ~180K（vs Stage-1 的 ~2.1M）

## 七、数据流图

```
┌─ Stage 1 (frozen) ─────────────────────────────┐
│  inp_feat → CE Backbone → H_1                  │
│  H_1 + y + x_p + σ → LMMSE → (x̂, v_x)         │
│  x̂ + v_x → Demapper → LLR                      │
└─────────────────────────────────────────────────┘
                      ↓
┌─ μ_x computation ──────────────────────────────┐
│  QPSKPosterior(x̂, v_x) → μ_x                   │
└─────────────────────────────────────────────────┘
                      ↓
┌─ Residual ─────────────────────────────────────┐
│  y_res = y - H_1 @ (x_p + μ_x)                 │
└─────────────────────────────────────────────────┘
                      ↓
┌─ Feature Tensor (8 channels) ──────────────────┐
│  [y_res, H_1, μ_x, v_x, |LLR|] → cat           │
└─────────────────────────────────────────────────┘
                      ↓
┌─ Stage 2 (trainable) ──────────────────────────┐
│  ChannelRefiner(8ch) → ΔH                       │
│  H_2 = H_1 + ΔH                                 │
└─────────────────────────────────────────────────┘
```

## 八、关键决策

| 决策 | 选择 | 理由 |
|------|------|------|
| Loss 域 | 2D grid (1326维) | 等效于 full H，但计算便宜 |
| 残差特征 | $y - H_1(x_p + \mu_x)$ | 比 simple SIC 更符合 turbo 原理 |
| $\mu_x$ 来源 | QPSKPosterior | 考虑决策不确定性，低 SNR 更干净 |
| Batch Size | 64 | H_flat 内存限制 |
| Refiner 宽度 | 64 ch, 3 blocks | ~180K 参数，学习修正而非完整信道 |
| $\|LLR\|$ 通道 | 平均两个 bit 的 \|LLR\| | 避免单个复符号的 bit 级 LLR 歧义 |

## 十一、原因分析

### 11.1 推翻的诊断：问题不是"LLR 撒谎"

高 SNR 时 LLR=50 是**正确的**，不是异常。

- LLR=50 表示"我对这个符号判决非常有信心"
- 这是真实信息，不是"膨胀的假情报"
- 强行 clamp(LLR, max=5) 会扔掉真实置信度信息——这才是破坏算法

### 11.2 真正的根因：自干扰地板（Self-Interference Floor）

高 SNR 下 NMSE 不降反升，这是 AFDM SP 全域系统的经典自干扰地板现象：

$$NMSE_{floor} = \frac{\mathbb{E}\|Ĥ − H\|²_F}{\mathbb{E}\|H\|²_F} \approx \frac{P_{interference}}{P_{pilot}}$$

**物理解释**：
- 接收信号：$y = Hx_p + Hx_d + n$
- LMMSE 只知道 $x_p$，不知道 $x_d$
- 当噪声 $n → 0$（高 SNR），数据符号对导频区域的自干扰 $Hx_d$ 成为唯一误差来源
- 该误差与 SNR 无关，所以 NMSE 不降反升
- **这是 SP 系统的结构性限制，不是 LLR 的问题**

### 11.3 Stage-2 没突破的本质原因

当前残差构造：
$$y_{res} = y − Ĥ₁ (x_p + μ_x)$$

问题在于：

1. $μ_x$ 是数据符号的后验均值，这个操作原理上正确
2. 但 **Ĥ₁ 本身包含 ~20% 系统误差**（来自自干扰）
3. y_res 里不只有"CNN 需要修正的信道误差"，还混杂着 Ĥ₁ 的自干扰污染
4. CNN 从被自身错误污染的残差中学习修正量——**这是在和自己打架**

### 11.4 关键洞察

残差构造的正确性依赖于 Ĥ₁ 的准确性，但 Ĥ₁ 本身就是问题所在。这形成了一个"自我放大"的误差循环。

# 实验总览：阶段五至阶段七基线冻结

## 目的

本文件用于在继续修改算法之前，冻结当前已经完成的阶段五、阶段六、阶段七实验结果，明确：

- 已经知道什么
- 还不知道什么
- 当前最可信的原因判断是什么
- 证据分别在哪些文件里

本文件只做研究状态沉淀，不新增实验，不改任何模型代码。

## 当前主线与研究问题

当前项目已经从“是否要继续 expanded OMP + hard pruning”转到“在保留传统 joint 骨架的前提下，深度学习究竟应该接管哪一小步”。

当前主问题不是“要不要学习”，而是：

- 现阶段收益主要来自哪里：
  - scaffold modernization
  - 还是少量可学习参数
- 传统算法里真正值得让学习模块接管的局部规则在哪里

## 阶段五封存结论

阶段五后期围绕 `Expanded OMP + confidence-aware hard pruning` 做过一次病理切片诊断。该方向当前已封存，不再作为近期主线推进。

核心归档结论：

- enlarged support 本身没有把 refit 子字典搞成病态矩阵
- `fixed_lambda = 1e-4` 下的 refit solver 没有表现出误差爆炸
- detector 在固定真信道下能够正常 free-run 到 `1e-3` 量级
- 更可疑的主因是 outer-loop 映射不收缩，而不是单个模块直接崩坏

当前决策：

- 这条路线保留归档，不继续围绕“矩阵病态 / refit 爆炸 / detector 自残”反复调参
- 若后续重启，应切到外环收缩性与 `H` bias 累积机制，而不是继续启发式 hard pruning

阶段五主证据：

- `afdm_sp_joint_unrolled_backup_pre_expanded_rollback_20260312_232814/afdm_sp_joint_unrolled/实现方案_阶段五_JointSparseUnrolled.md`

## 阶段六：Stage 6 scaffold 冻结

阶段六的核心目标，是验证：

> 保留传统 Joint 高层骨架，只学习少量连续超参数，是否足以拿到有效收益。

当前已实现并验证的 4 组 ablation：

- `fixed`
- `lambda_only`
- `alpha_beta_only`
- `lambda_alpha_beta`

统一协议：

- 训练：`teacher_cache`，`frames-per-snr = 20`，`snr = 5/10/15/20/25`，`epochs = 1`
- 验证：`frames = 100`，`snr = 15/20/25`

### 阶段六 verify 冻结结果

| Mode | 15 dB | 20 dB | 25 dB | 结论 |
| --- | --- | --- | --- | --- |
| `JointOMPMP` | `1.8291e-02` | `1.0215e-02` | `5.4980e-03` | classical baseline |
| `fixed` | `2.0039e-02` | `4.9707e-03` | `4.5117e-03` | `20/25 dB` 明显优于 baseline |
| `lambda_only` | `2.0039e-02` | `4.9707e-03` | `4.5117e-03` | 与 `fixed` 几乎完全重合 |
| `alpha_beta_only` | `1.9990e-02` | `4.9707e-03` | `4.5215e-03` | 仅有极小偏移 |
| `lambda_alpha_beta` | `1.9990e-02` | `4.9707e-03` | `4.5215e-03` | 与 `alpha_beta_only` 基本等价 |

阶段六当前最重要的事实：

- Stage 6 的 4 个版本都在 `20/25 dB` 明显优于旧 `JointOMPMP`
- 但 4 组 ablation 之间差别极小
- `fixed` 与 `lambda_only` 几乎完全重合
- `alpha_beta_only` 与 `lambda_alpha_beta` 也几乎完全重合

阶段六当前最可信判断：

- 现阶段 Stage 6 的主收益首先来自 **Stage 6 scaffold 本身**
- 当前 residual 参数学习尚未被单独证实为主要收益来源
- `15 dB` 仍未被这组全局小标量自由度接住

## 阶段七：Strict Traditional scaffold 冻结

阶段七的目标，是把“scaffold 改进”与“参数学习收益”进一步拆开：

- 旧 `JointOMPMP`
- strict traditional modernized scaffold
- Stage 6 scaffold

其中 strict traditional 分支尽量贴近旧 `JointOMPMP` 的数值流程，但用当前项目里的可训练/可展开实现重新落地。

统一协议：

- 训练：`teacher_cache`，`frames-per-snr = 20`，`snr = 5/10/15/20/25`，`epochs = 1`
- 验证：`frames = 100`，`snr = 15/20/25`

### 阶段七 verify 冻结结果

| --- | --- | --- | --- | --- |
| `JointOMPMP` | `1.8291e-02` | `1.0215e-02` | `5.4980e-03` | classical baseline |

- `TradParam classical_full` 没有稳定超过 `TradParam fixed`

## 当前最可信的研究判断

截至当前冻结点，最稳的共识基线是：

1. 阶段六和阶段七都表明，现阶段主收益首先来自 scaffold modernization，而不是小标量 residual 学习。
2. 阶段七说明 strict traditional scaffold 在低 SNR 更稳。
3. 阶段六说明 Stage 6 scaffold 在中高 SNR 更强。
4. 当前“学参数增益不明显”的更可能原因是：选中的全局标量不是系统最痛点。
5. 下一步应优先寻找“传统 heuristic 明显失真的局部规则”，而不是继续盲目增加几个全局小标量。

换句话说，当前不是“学习没用”，而是：

- 当前选中的 `lambda / alpha / beta`
- 或 `lambda_ls_factor / gamma_h / gamma_x / pic_damp`

还没有被证实正好落在系统最脆弱、最值得学习接管的位置上。

## 已证实 / 未证实

### 当前已证实

- expanded OMP + hard pruning 路线当前主要矛头不在矩阵病态、solver 爆炸或 detector 自残
- Stage 6 scaffold 在 `20/25 dB` 明显优于旧 `JointOMPMP`
- strict traditional scaffold 在 `15 dB` 更稳，且其 `fixed` 版本已整体优于旧 `JointOMPMP`
- 旧 `JointOMPMP` 与当前更强版本之间的差距，首先来自 scaffold / 数值实现方式

### 当前未证实

- Stage 6 的 residual 参数学习是否带来了稳定额外收益
- strict traditional 的 classical scalar 学习是否带来了稳定额外收益
- 低 SNR 的主瓶颈究竟更偏向 support 结构、uncertainty calibration，还是 outer-loop trust/gating

## 下一步实验队列

本文件只冻结现状，不实现以下工作。当前建议队列如下：

1. 先做 oracle 参数扫描，判断哪些参数真的存在可观 oracle gap。
2. 再定位当前算法里“传统 heuristic 明显失真”的局部规则。
3. 优先尝试轻量的局部学习修正，而不是继续堆全局标量。
4. 重点候选方向：
   - support cluster / leakage-aware 结构先验
   - detector uncertainty / variance calibration
   - outer-loop 的局部 trust / selective gate

      - `mean_learned_scale = 1.898`
      - `scale_range = 0.063 ~ 14.159`
      - 但当前 learned objective 更像在优化统计 calibration，而不是当前 Stage6 真正需要的 task-aware interface
      - 因此仍未超过 `v1`：
        - `final_mean_ber = 7.2908e-04`
    - 阶段十二的正式结论因此固定为：
      - output-side recalibration 主线继续成立
      - 但当前最实用版本仍是最简单的 `v1`
      - `hybrid_v3` 与 learned recalibration 只作为证据保留，不升级为新主线
    - 当前进一步不建议：
      - 继续细抠 `hybrid_v3`
      - 继续小修小补当前 learned objective 后反复细扫
      - 回到 `alpha`
      - 回到 gate
      - 回到 detector internal sigma
    - 若后续继续沿 learning 推进，阶段十二给出的最硬约束是：
      - 下一代 learned module 必须优化真正的 task-aware uncertainty interface
      - 不能只优化统计 calibration 本身
  - 阶段十三 `outputs_stage13_anchor_smoke_v3` 的进一步冻结共识：
    - `frame_worst_late_optimism` 已经真实接通，不再是 `nan`：
      - audit 4 条 profile 均有 `frame_rows=500`
      - 主 summary 也已有 `frame_row_counts: fixed_best=500, v1=500, variant=500`
    - 这意味着阶段十三之后，late-risk 判断已经可以视为可信证据，而不再只是辅助指标
    - 在真实 frame-level 风险接通后，anchored learned 仍未超过 `v1`：
      - `fixed_best = 1.2891e-03`
      - `v1 = 1.3184e-03`
      - `anchored learned = 1.3184e-03`
    - 也就是说：
      - BER 只做到与 `v1` 持平
      - 但风险仍更高：
        - `v1 task_risk_score = 1.077`
        - `learned = 1.193`
        - `v1 frame_worst_late_optimism = 0.271`
        - `learned = 0.351`
    - `iter4 residual bound` 单独收窄已证明有效：
      - learned `iter4_rho` 已从前一版约 `1.721` 降到约 `1.515`
      - 但仍高于 `v1` 的约 `1.375`
    - 阶段十三因此给出的正式冻结结论为：
      - `v1` 继续作为当前最终、最实用的 uncertainty interface
      - anchored learned 只作为“frame-level 风险接线完成、BER 可追平 incumbent”的证据保留
      - 不升级为新主线
    - 当前进一步不建议：
      - 继续沿当前 learned scalar recalibration family 做更多 smoke / 正式版细扫
      - 继续围绕 `iter4` 做无止境的 loss / bound 微调
      - 回到 `alpha`
      - 回到 gate
      - 回到 detector internal sigma

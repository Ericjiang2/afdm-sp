## 顺序与依赖

`SRC → Phase 0 授权 → 配置/物理结构/导频几何 → 新协议授权 → 数值链路/独立审查/成本 → B_star → 八单元机制诊断 → 条件结构 oracle → 唯一路线 → 原型/经典强对照 → 冻结/独立确认/反证 → 动作裁决 → REVIEW`。

CSV `phase` 是执行顺序号，不是源文的 Phase 编号。`depends_on` 为逗号分隔的 issue ID；`run_if` 为显式条件表达式，执行器按证据判定，不能仅逐行盲跑。独立非GPU工作可交错；同GPU时延测量必须串行。

条件值来自有哈希的上游裁决：`physical_mapping_exists_and_underused` 来自 P0-02；`route` 来自 ROUTE-01，取 M / I-feedback / I-cancel / T / STOP；`cancellation_gate_passed` 来自 MECH-02，判据已在GATE-01前置冻结；预算、发射端与确认批准来自对应gate的用户授权记录；`viable_legal_candidate` 来自 DEV-01或合法桥接失败的审查证据；`proceed_confirmation` 来自 FREEZE-01样本量/成本评估，正式STOP或无候选时明确赋false；`confirmation_started` 来自真实运行账本。`M-01_executed` 指实际执行通过，不能由条件排除产生。可选理论是否采用在方法冻结前决定。

执行时只有三种处置：

1. **执行并验收**：授权有效、依赖满足、条件真。按 AC 保存可重验的证据、必要代码审查/回归、任务相关 Git 交付；状态才可闭合。使用已有代码不免除所需路径验收。
2. **条件排除**：条件由上游证据明确判假。保存 `disposition:conditional_excluded; excluded_by:<issue>; evidence:<path>; reason:<理由>`，三个验收状态仅表示“排除处置已完成”，不表示实验运行。claim 保留未验证，并增加 `disposition:conditional_excluded`、理由与证据。必要的排除记录随任务提交后 git_state 才可已提交。账本/REVIEW 汇总必须把已验证与条件排除分开。
3. **待人类/外部条件**：授权缺失、证据未知、原件缺失影响审查、独立审核不可用或关键成本无法验证。写 `blocked:`，保持未开始/进行中；不能把未知当假来排除。未阻塞的授权范围内工作继续。临时故障不自动转 STOP；科学证据不足时按已批准停止规则形成有限结论。

所有依赖均按上述“执行验收或有证据的条件排除”满足。M不成立时 M-01/M-02 排除后 ROUTE-01 仍可运行。WIRE-04 仅要求所选路线真实完成，其余分支可有证据排除。合法原型实现阶段已确认不可实现时，以该审查证据处置剩余原型行；不能伪造烟测或强行跑DEV。无候选时，DEV/确认/反证等排除后仍必须完成 DECIDE-01 和 REVIEW。

FREEZE-01只需合法候选即可进入样本量/成本评估，不先要求“预算可装下”。输出 `proceed_confirmation=false` 时正常关闭该资源评估并排除确认、反证、最终计时及未启动的统计行。条件采用有证据的短路判断：正式STOP/no_candidate/预算不适配已令proceed=false，则不再等待confirmation_approved；proceed=true但授权未知时才阻塞。停止后不自动切第二条原型路线。不把资源停止伪装成性能失败。

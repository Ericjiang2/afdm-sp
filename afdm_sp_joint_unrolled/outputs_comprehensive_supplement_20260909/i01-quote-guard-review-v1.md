# I-01 quote guard revision

The six identified issues are addressed without changing checkpoints1/4, blocks1/2,8dB, six arms,72F cap, candidate counts20/18/16/12, or time-only feasibility rule. No GPU/receiver run was performed.

Contract generation must compute SHA256 over `json.dumps(payload, sort_keys=True, allow_nan=False).encode()`, where payload excludes exactly `config_sha256`, `ledger`, and `reservation_path`. The reservation's `contract_sha256` must equal that digest and its calls must be `{F:72,T:0,E:0}`. Required new contract fields are `protocol_sha256`, `source_root` (absolute frozen Python package directory), and `external_timeout_seconds` (integer). `source_sha256` must contain every `.py` under that root plus the absolute quote-runner file; the actually imported generator package must reside at that root. Design/checkpoint/protocol/source hashes are rechecked before calls and after calls, outside the receiver timer.

The external launcher must use an actual Linux ancestor invocation `timeout --signal=TERM --kill-after=15s <external_timeout_seconds>s ...`; the runner verifies `/proc` ancestor argv rather than trusting an environment attestation. Python deadline must be finite, future and at least15 seconds inside the external timeout duration. SIGALRM is armed before GPU/setup/generation and SIGTERM has the same failure handler; handlers are restored on exit. The external hard kill remains necessary if a native operation cannot service Python signals; such a kill may leave started/partial artifacts, not a fabricated failure JSON.

Before CUDA initialization, the runner sets `CUDA_VISIBLE_DEVICES` to the contract UUID, rejects a previously initialized CUDA context, requires exactly one visible device, and verifies its Torch UUID. If the property is unavailable, a current-PID GPU query after context creation must bind that PID to exactly the requested UUID. Exclusive-process checks run before and after measured calls; these are observed boundaries, not a proof against an unobserved transient intruder.

Output budget must cover72×32MiB plus256KiB failure reserve. The remaining full reservation must fit available disk before work/calls. Publications use bounded exclusive atomic publication and raw terminal snapshots receive the explicit output cap. Structured failure retains active identity, attempted/completed counts, partial active wall/CPU time, completed preparation costs and traceback, and blocks automatic re-entry. End-to-end receiver time retains graph/message instrumentation. Setup, generation, model construction, per-call controller/receiver construction and snapshots are separately recorded. Receiver timing still encloses final BP/demap/LDPC.

Design wording now says synchronized F **including** schedule graph observations/message hashes; its content SHA changed and must be regenerated in the new contract. The selection rule itself is unchanged.

Four mock-only guard tests passed: canonical binding/derived fields, finite deadline/output/call bounds and timeout argv, actual-device UUID/single-device checks, immutable preflight failure with no CUDA work. These tests do not establish GPU execution, hard-kill behavior under a stuck native kernel, real disk pressure, or equal-cost admission. Original COST-02 remains separate.

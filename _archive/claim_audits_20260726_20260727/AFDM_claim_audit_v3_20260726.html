§2 · 简报误差 vs 科学误差 — v2 的错分两类，修法完全不同

Asked v2 哪里错了。
Unasked 错因是什么——同样一句误判，若因简报不全，修简报协议即可、零实验成本；若因科学保守，则大概率不该修。混淆两者会把「过程改进」误当「结论翻案」。
Mechanism 判别式：把 v2 的每条判断替换为「在当时简报下的最优推断」重演一遍——重演后仍会犯的 = 简报误差；重演后仍会坚持的 = 科学保守。

2A · 信息不全导致的误判（v2 之错，源头在简报通道，修复见 §9）

#v2 误判事实该误判的传导损害
A1（=M1）「coded 域无 geom/ach 分离臂 ⇒ 白化 coded 归因需补实验」双臂自始同帧并行、全五点、锚已 smoke行动清单多算一项最贵实验（约数天）；§3.6/行动1 的「补臂」指令空转；RED 句挂错理由（该挂「差值未报」）

A3「SNR7 锚点 scorer 未注明 ⇒ 按不明部署臂处理」身份已登记 = geom 臂损害最小（v2 的处理是保守正确的），但暴露同一简报通道问题

对简报流程的三条硬约束（完整 schema 见 §9）：① 臂清单完整性——每次简报必须列出「在跑的全部臂」（含未出数的），"没有数字" 与 "没有臂" 是两个字段；② scorer 身份必填——任何臂的任何数字，无 scorer_id 不得入表；③ n 与完成标志必填——每个数字带 n_frames / complete?，interim 数字自动携带 supersede 指针。审计侧的对偶规则（v2 自己的推理修正，同等重要）：not-in-briefing ≠ not-run——简报里的缺席只允许生成问句（"该臂是否存在？"），不允许生成判定（"该臂缺失"）。v2 在 A3 上做对了（标 unidentified、要身份），在 A1/A2 上做错了（从缺席直接推缺失）。

2B · 科学上仍成立的保守（v2 之对，v3 不翻案）

  • coded 白化 claim 冻结——臂在不改变「差值今天不可读」；冻结依旧，只换理由。
  • "survives channel coding" RED——直到五点终表+正确臂引用。
  • interim 禁引 / 4 帧禁引 / SNR15 coded 永久禁——全部维持；SNR8 从 4 帧到 260 帧改变的是信号强度，不是引用资格（800f 才是资格线）。
  • "near-optimal" 禁令——v2 时是预防性措辞纪律，v3 起是实测事实（PCSI gap 2.6× 就摆在那）。保守被数据追认，这是审计最希望发生的事。
  • 学习 null 不回潮 / 跨 harness 禁配对——维持。

6.2 历史无指纹 runs 的处理

6.3 C1 验收标准（改写后）

  • 主路径 device-matched bit-exact：GPU↔GPU、登记 dtype / kernel / determinism 设置，repo-only checkout 重放归档 shard（建议 gateA_s15firm 子集）→ 逐帧误差向量逐位 diff。等 GPU 修复，与 E6 同批（~1 天）。

  • 备用容差路径（仅当匹配设备长期不可得）：先在新鲜对照帧上实测 CPU↔GPU 翻转率基线，再要求回放差异 ≤ 该基线，且成品标注 tolerance-replay 而非 bit-exact——两个词在论文里不可互换。

6.4 配对边界（维持并前向适用）

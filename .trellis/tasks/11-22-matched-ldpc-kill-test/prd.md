# 21-l02 生死检：按内环 EXIT 曲线匹配的不规则 LDPC 对 (3,6) 规则码

来源：漏斗卡 `ideas/cards/I-20261121-l02.md`（L3，Astra 第三次放行 PASS）。Eric 批示：继续（限时生死检）——微创+反直觉符合品味；先造 n = 2048 实码跑 200 帧验真，端到端净赢 ≥ 0.8 dB 立项，否则毙。执行者：Codex（GPT-6.2 Sol）。

## 要回答的一个问题

把叠加导频接收机里的 (3,6) 规则 LDPC 换成同码长、同码率、度分布按"检测 + 信道重估"内环 EXIT 曲线匹配的不规则 LDPC，有限码长、真实译码轨迹下，端到端能不能在同一误帧率上净赢 ≥ 0.8 dB？

卡片的模型预测（无限码长、一致高斯反馈）：6.5 dB、ρ = .30、L28（K = 224）上，(3,6) 十轮译不出（实测 FER .85），匹配码第 5 轮过线；三档负载的隧道门限低 1.1–1.45 dB。已知折扣：res-20261009-01 记录模型预测能启动的帧实际只有 29%–50% 译出，所以这次检验就是看折扣后还剩多少。

- 匹配度分布（边视角）：`lam2 = 0.45, lam3 = 0.30, lam30 = 0.25, dc = 6`（`ideas/l2/out3/exit_schedule.json` 的 `6.5dB_L28.sp_best_name`）；白噪声最优对照：`lam2 = 0.20, lam3 = 0.40, lam12 = 0.40, dc = 7.5`（同文件 `awgn_best`）。搜索与调度脚本：`ideas/l2/l2_exit_tunnel.py`、`ideas/l2/l2_exit_schedule.py`。

- C1 线接收机驱动：`experiments/headroom_ladder_20261008/driver_c1e.py`（l02 的配对注入检验已原样调用过它）。

## 要求

1. 造码：用 PEG（或等价的环长优化构造）造 n = 2048、码率 1/2 的匹配码；同法造白噪声最优码作第三臂。记录实际度分布、girth、构造种子；规则码沿用现有 `build_code`。改动只加新函数，不改现有函数的行为。
2. 接收机与工作点：在 C1 线接收机上测（内环曲线就在这里量的，换接收机会混进第二个变量）。ρ = .30，负载 L28（K = 224）为主、L16 为辅；10 个外轮，调度与现接收机一致。SNR 扫描覆盖 (3,6) 的 1% 和 10% FER 穿越点附近，并下探到匹配码的过线点（预计 5.3–6.8 dB，按 0.25 dB 步长）。
3. 帧数：每个 SNR 点至少 200 帧，三臂同帧同噪声配对；新帧，不用 500–599（那是量内环曲线的帧）。
4. 判据先写后跑：判据、帧号、SNR 网格、度分布在运行前提交（`PREDICTIONS.md`），运行后不改。
5. 主判据：在 L28 上，匹配码相对 (3,6) 在 10% FER 处（主）与 1% FER 处（辅，帧数不够就只报区间）的 SNR 差。净赢 ≥ 0.8 dB → CONTINUE（立项，回 Eric）；< 0.3 dB 或匹配码不优于白噪声最优码 → KILL；之间 → MIDDLE，报区间，由 Eric 定。差值用配对 bootstrap 给 95% 区间。
6. 结果记录：`results.json` 带 `_argv`、`_config`（项目 Git 规范必备字段）；远程大文件留 deinlab，路径与 md5 记进任务 notes。
7. 代价上限：约 1–2 天编码 + 不超过 20 CPU 核时（deinlab，遵守项目 CLAUDE.md 的服务器规则：只写 `/data/guoyikun/`，tmux `g_` 前缀，先查负载）。超出就停下报 Eric。

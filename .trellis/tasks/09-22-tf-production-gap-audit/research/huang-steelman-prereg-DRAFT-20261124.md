## 0. 要回答的问题
现稿的主张是：译码失败后，在 F0 的支撑上做**局部、固定预算的交换**（`CODELAY` 分支，最多 2 次编辑），比现有做法更好。
最可能的审稿攻击是："这就是 Huang 等 2010（EURASIP JASP，doi 10.1155/2010/460379）搬到 AFDM 上。"那篇做法是：校验没过时，把译码出的软符号当成额外导频，在整本字典上**从头重新找径**（OMP 或 BP），再译码，直到校验通过。
我们从没测过这一臂。F0 本身不做数据辅助重新找径：第 0 轮只用导频找径（`pilot_front`），之后每轮只在固定时延上把多普勒在 ±0.75 bin 内微调（`twofft.time_refine`），见 `experiments/sp_afdm_native_joint_reviewed_20260921/src/native_twofft.py`。

本检验回答：同一批帧、同一个触发、同一个下游检测器和译码器、同样的多普勒分辨率下，**局部交换（CD）对全局数据辅助重捕获（HG）在精度和每次触发的耗时上各差多少**。

## 1. 臂（全部共用同一个 F0 状态和触发：F0 第 2 轮校验子不为 0）
| 臂 | 支撑怎么更新 | 之后的链路 | 说明 |
|---|---|---|---|
| `F0` | 不更新 | — | 归档行 |

| **`HG`（主对照，steelman）** | 参考信号取 `pilot + mu`（mu 由 F0 第 1 轮 APP 经 `moments(·, 1−ρ)` 得到，与 CD 用的参考相同）；在**与 CD 同分辨率**的字典上从头贪心找径（时延 0…`l_max_cap`，多普勒 −3…3、步长 .25），沿用 `pilot_front` 的同一个 OMP（`BaselineInitializer('B0-p2-s0.5')`：固定挑 24 个原子；新建实例时把 `dictionary_limit` 从 515 放大到 103 × 25 = 2575，不改冻结源码；除已知 σ² 外不用任何真值） | 先走 F0 自己的每轮信道精修 `time_refine(mode='soft', max_paths=8, rounds=2)`，再接与 CD 相同的 `scalar_joint` 和 LDPC；校验通过即停，否则用新的 APP 再重捕获一次，**最多 2 遍** | Huang 式做法：从头重捕获，迭代到校验通过 |

| `HGint`（次要） | 同 `HG`，但字典用 `pilot_front` 原样的整数多普勒（−2…2） | 同上 | 量字典分辨率的影响 |

## 3. 主判据（三项，Bonferroni，各 98.33% 区间；两场景等权平均；穿越点、截断与自助规则全部沿用 ρ 扫描 §7 的已测试实现，物理帧为抽样单元，20,000 次）
- **Q1（固定 ρ = .30）**：Δ30 = c_HG(.30) − c_CD(.30)（1% 误帧率穿越点，dB；正值表示 CD 更好）。
- **Q2（各取最优）**：Δbest = min_ρ c_HG − min_ρ c_CD（6 点 ρ 网格）。
- **Q3（归因，等效检验）**：Δbest_Z = min_ρ c_Z − min_ρ c_CD。区间整体落在 [−0.5, +0.5] 内判 `Z_EQUIVALENT`，即增益属于交换架构，论文的方法写成"触发后局部交换"，打分用 Γ = 0 或 `CODELAY` 都可以。下界 > 0 判 `CD_NEEDED`，协方差确有端到端增益。上界 < 0 判 `Z_BETTER`。其余判 `Z_INCONCLUSIVE`。Q3 与 Q1、Q2 的判定互相独立，分开报告。
  - 跑前预测（Claude）：`Z_EQUIVALENT` 65%，`CD_NEEDED` 15%，`Z_BETTER` 5%，`Z_INCONCLUSIVE` 15%。

判定（以 Q2 为准，Q1 只报一致性；跑后不改名）：
| 判定 | 条件 | 对论文的含义 |
|---|---|---|
| `CD_AHEAD` | Q2 下界 > 0 且点估计 ≥ 0.5 dB | 故事成立：局部交换胜过已发表的全局重捕获；HG 写进主表当基线 |
| `CD_SLIGHT` | Q2 下界 > 0，点估计 < 0.5 dB | 精度上只小胜；论文主打转向耗时（见 §4） |
| `EQUIVALENT` | Q2 区间整体落在 [−0.5, +0.5] 内 | 精度打平；值不值得写取决于每次触发的耗时差 |
| `HG_AHEAD` | Q2 上界 < 0 | CD 被已发表做法支配；接收机部分改用 HG，论文只剩"何时重搜、各花多少时间"的决策图 |
| `INCONCLUSIVE` | 其余 | 如实报告，不追加运行，由 Eric 定 |

0.5 dB 的来源：l34 检测器配平后 CD 对 SBL 的领先恰为一个 0.5 dB 测试档；ρ 扫描各穿越点的区间半宽约 0.2–0.5 dB。冻结前用归档的 CD 穿越点区间再核一次这个尺度是否合适。

## 7. 设计有效性
- **单因子**：HG 与 CD 共用同一个 F0 状态、同一个触发、同一个参考信号 `pilot + mu`、同样的多普勒分辨率、同一个检测器和译码器。不同的只有支撑更新规则（从头全局重捕获，还是局部固定预算交换），以及各自方法原本的精修步骤（HG 用 F0 的 `time_refine`，CD 用 `reopen_geometry` 的局部精修）。
  "HG 最多 2 遍"是有意给对手的让步（steelman）；`HG1` 把这一项分开。
- **杠杆**：ρ = .30、5 dB 时 CD 已救回 .91–.93 的触发，所以在高 ρ 上 HG 几乎没有赢的空间。有区分力的地方在低 ρ（.15–.25），那里 CD 开始失效、数据能量占比最大，Q2 正好覆盖。
- **统计单元**：物理帧，所有格子共用同一组自助抽样，与 ρ 扫描相同。
- **真值**：评估臂不用任何真值（σ² 已知除外，沿用现稿口径）。真数据符号只出现在门 G3 里。

## 8. 事前验尸
- **HG 赢了**：最可能的原因是软参考能量大、全局搜索直接看见弱径，这是真实结果，不是缺陷。要先看 HG1 是否也赢，排除"只是多跑了一遍"。

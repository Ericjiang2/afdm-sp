## Cost boundary and limitations

- `native_controls.receive_control` is the common complete wrapper for EP/PBi; TF uses frozen `native_twofft.receive`. No I1 warm-up or oracle geometry is injected into any native method.
- EP cyclic bandwidth is the observed delay span, not simply P. Delivered solver cost is O(N b²+b³), with a labeled dense branch when b≥N/2. TF inner path contractions cost O(NP+N log N) per iteration; this excludes its separately charged acquisition/refit/decoder costs. The dense PBi implementation materializes O(PN²+4N²) arrays. These are source-derived implementation costs, not complexity lower bounds for the literature families.
- Static code/context construction is separately timed and amortized only under the same allowance. Warmups are separately logged. Import/runtime/static-code process memory must remain visible in isolated memory reports. Peak whole-process RSS must not be inferred from named array sizes alone.
- Pilot acquisition constructs the frame-dependent N×515 dictionary online, with a40-candidate observed initializer before grouping to at most8 delays. It is not an O(NP)-only complete pipeline. Each trial in the physical variable-projection search is online work.
- Decoder-ready timestamps and complete receiver return time have distinct meanings. Hooks/instrumentation/storage inside a receiver callback are charged to complete time. Truth-based scoring and input generation are offline and separately logged. Kernel benchmarks cannot substitute for complete receiver timing.
- The refit solves an observed-data variable-projection objective with Gamma and ridge lambda=sigma². The inner gain prior has covariance I/P; its precision is P. These are different estimators/roles, not a single interchangeable regularizer or a proven common ELBO.
- PBi's candidate-dependent pilot/gain-variance treatment and EP's proper-complex covariance projection are retained and disclosed; no exact noncircular or author-implementation label is used.

Exact source/environment/code/input manifests, named per-stage costs, and isolated array/process measurements accompany this map. Any cost not measurable by the explicit-array instrument must be labeled excluded from that array subtotal, rather than declared zero.

## Noise / coordinate convention

Executed sigma² is E|w|² for a proper-complex sample; each real component has variance sigma²/2. The complex Gaussian precision above therefore uses1/sigma², not the real-stacked paper's component precision without conversion. The delivered code uses its own qualified positive-chirp/positive-Doppler convention; the manuscript must use that convention consistently instead of mixing the paper's negative-chirp DAFT definition into its operators. The exact CPP/dense comparison checks the executable convention. Proper-complex projection discards pseudo-covariance; it is an explicit approximation, not algebraic equivalence to full real-valued EP.

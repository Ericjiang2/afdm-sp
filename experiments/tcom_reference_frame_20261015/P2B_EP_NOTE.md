## 2. 推导

单个导频（在 DAFT 域位置 m_p）经过任意路径 (l, nu)，|nu| <= alpha_max，落在 y 的 (m - m_p) 约等于 K l + nu 处，因此导频的响应占据
`(l_max + 1) (2 alpha_max + 1)` 个 bin（整数多普勒时精确，分数多普勒再多出 sinc 旁瓣）。为了让数据不落进这个区域，
也不让数据的响应落进导频自己的观测窗，导频两侧各需要 Q = (l_max + 1)(2 alpha_max + 1) - 1 个零符号（Bemani 等 2023 的保护带），共 2Q + 1 个符号用于导频加保护带。

- **主场景（l_max = 102，alpha_max = 2）**：响应区 103 x 5 = **515** bin；Q = **514**；2Q + 1 = **1029 > N = 1024**。
  保护带本身已经大于整帧，数据符号数 N - (2Q + 1) = **-5 < 0**。分数多普勒（协议里的 xi 额外 bin）只会更糟。
- 因此在 c1 = 5/(2N) 的生产系统里，EP-AFDM 无法在主场景（时延上界 102）放下任何数据符号；这是 SP（叠加导频）在该场景的必要性论据。
  与接收机无关，也与导频能量分配无关。

## 3. 数据符号数随 l_max 的变化（alpha_max = 2，N = 1024）

| l_max | 响应区 (l_max + 1) x 5 | Q | 2Q + 1 | 数据符号 N - (2Q + 1) | 占 N |
|---|---|---|---|---|---|
| 25（场景 S） | 130 | 129 | 259 | **765** | 74.7% |
| 50 | 255 | 254 | 509 | 515 | 50.3% |
| 75 | 380 | 379 | 759 | 265 | 25.9% |
| 100 | 505 | 504 | 1009 | 15 | 1.5% |
| 101 | 510 | 509 | 1019 | 5 | 0.5% |
| 102（主场景） | 515 | 514 | **1029** | **-5** | 不可行 |

信息比特数 = 数据符号数 x 2 x 码率（QPSK，码率约 1/2），所以 EP 的吞吐随 l_max 线性下降，到 l_max = 102 为零；SP 的信息比特恒为 1024。

## 4. 注意事项

- 这里用的是生产系统的 alpha_max = 2（c1 = 5/(2N)），它由几何律的 nu_max = 1.62 和 UWA 律的 |k| <= 2 决定。若改用 alpha_max = 1（c1 = 3/(2N)），
  主场景的保护带是 Q = 308、2Q + 1 = 617（还剩 407 个数据符号），但此时 nu_max = 1.62 超出了可无混叠分辨的多普勒范围，所以不是等价设计，不在本比较内。
- 发射端不知道单帧实际的最大时延，保护带必须按设计上界 l_max 开。主场景中单帧最大时延的均值约 76 个采样点（`S0_NOTES.md`），
  但上界取 102（接收机银行边界），所以不能按单帧缩小保护带。
- 缩小时延跨度的场景 S（l_max = 25，时延律按 25/102 缩放并截断在 25）是 EP 唯一可行的比较点：Q = 129，保护带 259，数据 765；
  LDPC (3,6) n = 1530 由项目自己的构造器生成（`e1_ldpc.build_code(1530, 3, 6, seed=20260726)`），秩 763，实际 k = 767。

## 5. 场景 S 与 EP 接收机的实现记录（实现说明 I2）

- 场景 S（`gen_fixed.Flags(fix_delay_cap, fix_delay_grid, geometric, fix_energy, delay_scale=25/102, l_trunc=25)`）：指数增量均值 0.196 ms（3.14 个采样点），8 条路径，
  超过 25 的帧重抽。MC 100000 帧：首次接受率 41.75%（独立拒绝采样器 41.55%，z = 1.61），**重抽率 58.2%**（平均 1.395 次重抽/帧，最大 17 次）；时延跨度 KS p = 0.85；最大时延 25，时延互异。开关全关时仍与冻结生成器逐比特一致（`out/s0/GATES.md` G-S0a，1000/1000）；P1 的 U、G 场景相对 P1 时代的 `gen_fixed.py` 逐比特不变（`out/p2b_gates` P2b-G0，md5 cb9be5ea…）。
- EP 帧：导频在 DAFT 索引 512，两侧各 129 个零保护符号，765 个数据符号；LDPC (3,6) n = 1530 由 `e1_ldpc.build_code(1530, d_v=3, d_c=6, seed=20260726)` 生成（与 n = 2048 的码同一构造器与同一 seed）。
  Gallager 构造的三个块各自的行和相同，rank 为 763（n = 2048 的码秩 1024，k = 1024），所以实际 **k = 767**（码率 0.5013）；goodput 里 EP 按 767 比特计，对 SP 不利（保守）。
- 检测器：采用自写的软输入 LMMSE turbo 检测器（2 轮，LDPC BP 50 次，保护带按已知零处理，导频用估计/真实信道消去）。冻结的固定信道 TF 检测器（`interventions.run_fixed_channel`）不能在不改冻结代码的前提下使用：
  它对 1024 个 QPSK 符号用同一个标量先验方差、绑定 2048 比特码的映射，没有数据掩码，保护带的零符号无法表示。
- 估计器：阈值 P_FA = 1e-3（5 bin 窗能量 / sigma2 ~ Gamma(5,1)，在任何调参之前固定）；为避免强径的 sinc 旁瓣在相邻窗里造成假径，用"最强窗先检测—0.05 bin 网格加局部抛光—联合 LS—重估各径多普勒"的逐次消去；
  无噪导频帧上延迟 50/50 恢复、多普勒误差 <= 7e-4 bin；带数据时（rho_EP = 0.1）4.5 dB 路径召回 0.76（能量召回 0.96）、8 dB 路径召回 0.89（能量召回 0.99），无假径。
- 开发调参（独立熵，500 帧，6.0 dB，场景 S，EP 估计臂）：rho_EP = .05 / .10 / .20 / .30 的平均 goodput 为 693.37 / 765.47 / 767.00 / 767.00（错帧 48 / 1 / 0 / 0）；
  .20 与 .30 并列（均无错），按规则取较小者，冻结 `p2b_driver.RHO_EP = 0.20`。
- SP 臂是冻结接收机，银行仍覆盖时延 0..102（场景 S 的真实时延只到 25），所以 SP 在场景 S 里没有被缩小搜索空间——对 SP 不利（保守）。

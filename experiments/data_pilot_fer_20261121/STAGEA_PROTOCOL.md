## 问题
如果第 0 轮把 8 个真时延都找到（多普勒中心和增益仍由导频自己估），低导频（ρ ≤ .20）的最好穿越点能不能比基线的最好穿越点好出 0.3 dB 以上？

## 设定
- ρ 扫描同一条管线（`unified_cov_prospective_20261119/cstate.py`）：P1 U/G，N = 1024，LDPC (3,6)，QPSK，已知 σ²。
- 新帧 41000–41399（本地实验配置里没有用过这一段）。ρ ∈ {.05, .10, .15, .20, .25, .30}；SNR ∈ {3, 4, 4.5, 5, 5.5, 6, 6.5, 7, 8, 9, 10, 11, 12} dB。
- 每个键两个臂，用同一个观测：
  - **base**：F0（两轮），F0 未通过校验时接 `CODELAY` 交换（`run_branch` 'A1'，最多 2 次替换）；
  - **delay**：完全同上，只把第 0 轮支撑换成 8 个真时延。每个时延的多普勒中心取该时延上导频匹配滤波最大的整数列。做法是只在这一次 F0 调用里替换 `ctx.native.pilot_front`，调用结束后恢复。

## 门槛（运行前已通过，`out/stageA_gate.json`）
- G1：base 臂在 8 个 ρ 扫描存档键上复现存档的校验子、F0 错误数和 CD 错误数：8/8。
- G2：注入 `pilot_front` 自己的原样输出时，第 0 轮、第 1 轮的支撑和译码比特与不注入时逐位相同：8/8。

## 读数（冻结，不改标签）
- 穿越点：信息位 FER = 1%，在相邻两个 SNR 之间按 log10 FER 线性插值；第一个 SNR 已经低于 1% 记为 −∞，一直不低于记为 +∞。取 U、G 的平均。
- **基线最优** = base 臂在全部 6 个 ρ 上的最小穿越点；**低导频最优** = delay 臂在 ρ ≤ .20 上的最小穿越点。**余量** = 基线最优 − 低导频最优。
- 按 400 个帧配对自助 2,000 次（种子 20261121），每次重新取两个最小值。
  - 95% 下界 > 0.3 dB → **CONTINUE**（进入阶段 B）；
  - 95% 上界 < 0.3 dB → **STOP**（找全时延也换不来有用的收益，这条线停）；
  - 其余 → **INCONCLUSIVE**。
- 描述（应 Eric 转来的建议）：ρ ≤ .20 时 delay 臂仍失败的键，按最终支撑分三类：漏了有效径 / 支撑全对但按功率加权的多普勒误差 > 0.1 bin / 支撑全对且多普勒误差 ≤ 0.1 bin（剩下的归给增益或其他）。用来区分"找径不够"和"估准不够"。
- 另报每个 ρ、每条臂的穿越点，以及第 0 轮、第 1 轮和最终的漏径功率与多普勒误差（行文件里都有）。

## 竞争假设与预测
| 假设 | 预言 |
|---|---|
| H-acq：低导频崩塌主要来自第 0 轮漏径 | 余量下界 > 0.3（CONTINUE） |
| H-est：主要来自低导频下多普勒或增益估不准 | 余量小，delay 臂失败里"支撑全对但多普勒误差大"占多数 |
| H-loop：低导频下数据辅助回路接不住 | delay 臂在 ρ ≥ .15 有改善，再往下仍然崩 |

- Claude：CONTINUE .35 / INCONCLUSIVE .30 / STOP .35。
- Eric 转来的建议：余量 > 0.3 dB 的概率约 .55。

## Premortem
最可能与预期相反的原因是 H-est：低导频下即使时延全对，导频估出的多普勒和增益也不够准，第一次译码失败，回路起不来。上面那张失败分类表就是为了看清这一点。

# Classical F0 round-budget screen

Exploratory zero-learning screen for a future receiver direction. Native F0 is one pilot acquisition followed by two outer CE/detection/LDPC rounds. The LDPC core already terminates on a zero syndrome inside each outer round. This screen varies the number of complete outer rounds with the unchanged native CE, 20 detection iterations, default damping .3, and maximum 50 LDPC iterations. It adds an outer policy that returns the first zero-syndrome output up to its budget, or the last output if there was no pass. FER always uses information bits, so undetected errors count. Keep CSTATE and training outside this screen.

Use P1 U/G, physical rho=.3, frame IDs 18000–18159 and SNR {5.5, 6, 6.5, 7, 7.5, 8, 9} dB. Exactly 2,240 paired keys, one 10-round trajectory per key. Fixed K and early K prefixes share identical receiver states. Timed separately on one pinned CPU: frames 18000–18011, both scenarios, 6.5 and 7 dB. Run fixed 10 and physically early 10 in rotating order. Read complete per-round prefix times including array bookkeeping and, for early, the syndrome decision. Independently time original F0 at K=2. Stage times use the native pilot, CE, inference and decoder timers. Exclude frame generation and error/hash computation from latency. Record prefix/final parity against the original receiver on four keys with both first-round success and continued failure represented if observed. Code remains frozen and the experimental variant has a verified source binding.

Estimate FER=.01 crossing by the first log-FER bracket with zero floor 0.5/n. Report censoring rather than extrapolate. Use matched frame-cluster bootstrap (10,000 draws, seed 20261118) and 95% percentile bounds for each crossing and its difference from fixed K=10. For screening, the long-budget reference is usable when K=8 and 9 fixed point crossings each lie within 0.2 dB of K=10 in the same scenario. A shallow budget looks sufficient if at least one policy at K<=2 has a paired gap upper limit <=0.2 dB. A candidate depth bottleneck requires all K<=4 policies to have lower limits >0.2 dB and an eligible K>=5. Other cases are mixed or inconclusive. K=10 is a finite reference. A candidate bottleneck motivates a later comparison with tuned classical schedules, not an unfolding advantage claim.

Single-thread CPU workers on deinlab, <=16 workers with 16 cores reserved. Main <=8 min wall, timing <=4 min. Keep main rows and results in this experiment, no GPU and scratch only under /data/guoyikun/tmp.

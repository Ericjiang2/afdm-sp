## Coordinate and power definitions

The common nominal SNR is `-10 log10(sigma2)`, relative to **unit nominal total pilot-plus-data energy per useful DAFT symbol** before the channel. It is neither data-only SNR nor Eb/N0, and is not a per-frame received-power normalisation. Noise is added after the channel with `E|w|²=sigma2`, circular complex unit-variance draws `(nI+j*nQ)/sqrt(2)`. A unitary DAFT preserves this variance. Prefix energy is not included in the nominal axis. Pilot/data cross terms mean the realised `mean(abs(pilot+data)**2)` and realised received power need not equal one for each coded frame; they must be reported empirically, not interpreted as an arm-dependent SNR-axis error.

## Findings, interpretation and limits

- **OK — no static inter-arm power/noise offset identified.** The E3 internal .5 data power preserves the same physical SNR as P1. Known-noise detector inputs match the coordinate in which y is supplied. CRB uses physical coordinates consistently.
- **OK — P2b is an equal nominal total-energy comparison.** Different occupied-symbol energies and information-bit energies are intentional and disclosed. Equal Eb/N0 would be a different scientific question; this audit does not relabel the axis or change any card.
- **MINOR — audit-brief family-C wording.** “Jakes-4 rays per tap” can be misread as exactly4; actual law is 1+Poisson(3), mean4. The frozen E2 protocol `:50` and accepted card `res-20261017-02.md:37` already state it accurately. There is no confirmed generator-law mismatch.
- **OK — source-version distinction matters.** Current gen_fixed has the scenario-S extension added after P1. P1 config records MD5 `cb9be5ea91c0a9b1863758ed598de1c6`; the exact saved P1 source `experiments/tcom_reference_frame_20261015/out/p2b_gates/ref/gen_fixed_p1.py` matches it. Current MD5 is `9a3a987e0a1aaecde33018da5f38c74c`. Static diff is confined to new `delay_scale`/`l_trunc` flags, validation and their default-preserving draw/truncation expressions. Do not claim current source bytes were executed for P1. P1 physical/power/noise lines map to the captured source as recorded in definitions.json.
- **Validation limit — local frozen aliases.** P1 recorded paths use `sp_afdm_frozen_reviewed_20260921` and `sp_afdm_native_joint_reviewed_20260921`; local citations above use their MD5-identical `sp_afdm_frozen_20260920` and `sp_afdm_native_joint_20260921` copies. Thirteen core modules were checked against recorded P1 MD5; twelve match directly and gen_fixed matches the saved pre-extension source. This proves the inspected source mapping, not runtime output equality.
- **Validation limit — numerical checks pending here.** No distributional verdict, empirical SNR, operator match, or all-frame pairing verdict follows from this static table. Runtime audit must inspect/regenerate actual frame ranges and arrays, including P2b TEST entropy and E2CJ, before the final report claims completion.
